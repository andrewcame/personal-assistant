# Improvements

This folder tracks proactive improvements you've chosen to pursue — as distinct from [challenges](../challenges), which are open problems you're still working through. If delivery needs code or other changes, it is a Jira initiative tracked only in Jira: add the keys as the optional `jira:` label.

An improvement typically starts life as a recommendation from the **Priority Advisor** or **Idea Validator** agent, a job-spec or plan gap, or as something you decide to go after directly. It stays here while it's in flight. When it is done, Capture asks where the result goes and sets `outcome:` (`achievement`, `evidence`, `both` or `none`) and links the entry back.

## Numbering

One file per improvement, numbered sequentially (`01-title.md`, `02-title.md`, ...), using [templates/improvement-log.md](../templates/improvement-log.md).

## Lifecycle

Status values: **Not started**, **In progress**, **Blocked**, **Done**.

1. **Not started** — initiative identified, objective and next action defined
2. **In progress** — update the Actions & Progress log as it develops
3. **Done** — mark status Done, then use the **Capture** agent to write the outcome up as an achievement in `achievements/<year>.md`, linking back to this file
4. Keep the improvement file as the historical record of how it got there — don't delete it once done

## Working Boundaries

- This is for initiatives worth tracking over time, not day-to-day task lists — those stay in Notion
- Link to the goal(s) and role pillar(s) it serves where relevant; goals are usually higher-level than a single improvement
- Keep entries factual and dated so progress is easy to check later
