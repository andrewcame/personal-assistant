# QA Banding Reference

Purpose: capture the internal QA level framework in a way that can support:
- personal self-review calibration
- evidence mapping against expectations
- future review support for other people

Manager clarification:
- this framework is primarily a team calibration and development guide
- as a Test Manager, use it to set clear expectations, coach progression, and shape team goals
- it is not intended to be a strict personal scorecard for your own role
- Behaviour is tracked separately as the day-to-day performance review rating, not as part of the band matrix

## Structure

- rating-model.md
  - source of truth for tester levels, competency list, and rating requirements
- competencies/
  - one file per competency
  - includes score descriptions and examples for that competency only
- levels/
  - one page per QA level (1 to 8)
  - includes expectations across competencies

## How To Populate

1. Start with rating-model.md and confirm level/rating structure.
2. Fill each competency file in competencies/ with score definitions and examples.
3. Fill each level page with expected behaviors and examples for that level.
4. Keep examples observable and specific (what was done, how it was done, impact).
5. Update yearly or when role framework changes.

## Suggested Authoring Rules

- Keep wording neutral and reusable across teams.
- Separate expectation from evidence:
  - expectation = what "good" looks like at that level
  - evidence = example behaviors that demonstrate it
- Prefer short bullets over paragraphs for easier comparison.

## Test Manager Use Cases

- Build role-aligned goals for each QA based on current level and next-level signals.
- Calibrate review feedback by tying comments to explicit competency expectations.
- Spot team capability gaps (for example, strong delivery but weak influence) and set squad goals.
- Keep progression conversations objective by referencing shared examples and observable impact.
