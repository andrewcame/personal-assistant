# Initiatives

This folder tracks formal technical initiatives raised through the initiative process — proposals for engineering-backed change, as distinct from [improvements](../improvements) (self-directed, in-flight work you own directly) and [challenges](../challenges) (open problems still being worked through).

An initiative typically starts life as a challenge or improvement that's matured enough to need formal sponsorship, scoping, and engineering buy-in, and gets submitted using [templates/initiative.md](../templates/initiative.md).

## Numbering

One file per initiative, numbered sequentially (`01-title.md`, `02-title.md`, ...), using [templates/initiative.md](../templates/initiative.md).

## Lifecycle

1. **Draft** — being written/refined before submission
2. **Submitted** — raised through the initiative process, awaiting sponsorship/triage
3. **In progress** — approved and being implemented
4. **Done** — delivered; fold into an [achievement](../achievements) entry once complete, linking back to this file

## Working Boundaries

- Keep scope tight and phased — call out future work explicitly under "Out of scope" rather than expanding a single initiative
- Link back to the originating challenge(s) or improvement(s) under "Supporting Context"
- Flag unresolved dependencies/questions under "Open items to flag before this can be finalized" rather than leaving them implicit
